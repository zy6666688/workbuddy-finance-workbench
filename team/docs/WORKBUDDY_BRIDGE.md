# WorkBuddy 团队版配置与使用说明

WorkBuddy 调用团队版提供的 CLI 或 MCP，所有请求都以员工自己的团队版会话访问服务端。公司授权、权限撤销、成果归属、并发版本与审计仍由团队服务检查；AI 不提供复核通过操作。虚构客户验收范围与限制见[接入验收记录](WORKBUDDY_BRIDGE_ACCEPTANCE.md)。

## 管理员准备

1. 先完成团队版的数据库迁移、备份和服务启动。每台员工电脑需要 Node.js 20 或以上版本；团队服务本身按团队版部署说明使用 Node.js 24 和 Docker。
2. 将本项目安装到该员工的 WorkBuddy，安装器会备份已有配置，并分别更新桌面版 `mcp.json` 和兼容 CLI 的 `.mcp.json`，保留其他连接器。安装器还复制团队 CLI。安装完成后重新打开 WorkBuddy，必要时在 MCP 管理页由员工本人信任财务工作台连接器。
3. 负责人在团队版中创建员工账号、指定角色并分配客户公司。WorkBuddy 的登录账号不会自动成为团队版员工身份；每位员工仍须完成下方授权。
4. 正式部署应使用 HTTPS，服务地址由管理员提供；单机本机测试可使用回环地址，例如 `http://127.0.0.1:8080`。实际端口以部署配置为准。不要把会话、密码或真实客户附件写进 MCP 配置、聊天记录或代码仓库。

桌面版“自定义连接器”中的状态为启用、工具列表能看到 `team_whoami`、`team_order` 等，才表示 MCP 工具已加载。加载成功不代表团队账号已经授权；两者需要分别完成。修改 MCP 配置后，现有会话可能仍使用旧工具列表，应开启新会话或重启 WorkBuddy。

## 员工授权

使用团队版已分配的账号；首次使用的初始密码须先在网页更改。Windows 每位员工应使用独立 Windows 用户账户，勿共用桌面账号。由本人在本机 PowerShell 中运行（替换示例账号和地址）：

```powershell
node "$env:USERPROFILE\.workbuddy\apps\finance-workbench\team-cli.mjs" login --username=employee --url=https://team.example
```

仅允许 HTTPS，或本机回环 HTTP。密码在交互终端输入且不显示，不写入命令、聊天或 MCP 参数。短期会话由 Windows DPAPI 绑定当前 Windows 用户加密，存于该用户的本机应用目录；同一个 Windows 用户下运行的应用不构成彼此隔离的安全边界。服务端仍在每次请求时重新校验会话、角色与公司权限；授权文件不包含密码。更换员工时应使用不同 Windows 账号。会话到期或被撤销后需重新登录。

`logout` 撤销当前设备的服务端会话并清除本机授权，不影响其他设备；断网时保留本机授权并提示重试。`local-logout` 只删除本机授权，**不撤销服务端会话**。网页退出会撤销该员工的所有服务端会话。任务交接目录默认为当前用户文档中的 `ZY-Finance-WorkBuddy`，登录参数可设置 `workspace`。工具只能读取该目录内文件，下载时不覆盖同名文件。

## 接入范围

已提供客户、工作单、附件列表、工作流、任务创建、任务包生成与下载、成果上传与回传。任务包和成果操作以现有服务端版本、输入摘要与归属校验为准。AI 的回传不等于财务核验或独立复核。建档、资料收集、送审、复核、实际交付和归档继续在团队版网页完成。

MCP 工具和 CLI 命令行参数均不允许传入员工密码或任意 API 路径；员工密码只在本机交互式登录提示中输入。成果文件须由用户选择授权交接目录，并明确选择具体任务。MCP 服务重启或 WorkBuddy 重新启动不影响员工会话；服务端权限撤销不会等待重启才生效。

## 经办流程示例

1. 在团队版网页建立客户及工作单，完成分工、资料收集并进入经办处理。公司授权和资料清单由服务端校验。
2. 在 WorkBuddy 中说明客户、会计期间、任务目的和选用的资料版本。让它查询当前身份与工作单，再创建工作流执行记录。不要仅凭公司名称推断文件归属。
3. WorkBuddy 创建任务包并查询后台任务状态；完成后下载到交接目录。检查包内输入清单和摘要，使用任务包内材料处理。下载目录中的文件属于该 Windows 用户，使用后按照团队保管要求处理。
4. 将成果保存到交接目录，通过对应的任务执行上传；使用任务包的输入摘要、最新执行版本和成果编号回传。版本冲突、撤权或输入变更时先刷新并核实，不能强行重试旧数据。
5. 经办在团队版网页确认校验结果并提交，另一名有权限且未参与该批次经办的员工独立复核。复核通过后由员工在线下原渠道交付，再记录证据并归档。WorkBuddy 的输出、回传和校验提示均不代表审批完成。

## CLI 和 MCP 故障排查

| 现象 | 检查方式 |
| --- | --- |
| WorkBuddy 看不到 `team_` 工具 | 检查桌面 MCP 配置、启用和信任状态；开启新对话或重启后再试。 |
| 提示尚未授权或当前会话失效 | 员工在本人 Windows 账号下重新执行登录；密码不要发送给 AI。 |
| 客户或工作单不存在／无权访问 | 由负责人检查该员工的公司分配；权限撤销立即生效，不应借用别人的会话。 |
| 任务包未就绪或下载失败 | 查看 `team_jobs` 中任务状态和错误；文件已存在时换名称，工具不会覆盖。 |
| 成果上传或回传被拒绝 | 检查任务是否仍处于外部处理中、文件是否属于该执行、版本和输入摘要是否最新；退回后按工作单规则新建修订。 |
| 安装或首次改密后无法登录 | 检查服务地址、HTTPS、本机端口、账号启用状态；初始密码先在网页修改。 |

本机 CLI 可使用 `me`、`companies`、`orders`、`order`、`files`、`workflows`、`jobs`、`create-run`、`package`、`download-package`、`upload-result` 和 `return-run`。简单文本参数可使用 `--字段=值`；含数组或数值的复杂参数可通过标准输入传入 JSON，避免 Windows 命令行转义问题，例如 `'{"orderId":"工作单编号"}' | node "$env:USERPROFILE\.workbuddy\apps\finance-workbench\team-cli.mjs" order --json-stdin`。团队版只支持 Windows 上的本机加密授权；其它系统不能因接口能运行就认为已完成安全授权。

真实桌面 MCP 链路和 CLI 只读查询已用虚构客户验证，详见接入验收记录；不代表真实客户数据可以直接投产。
