# 资料收集、WorkBuddy 交接与团队管理

## 资料收集

打开客户月份后，先在顶部的批量上传区选择文件用途，再一次选择多个文件。每批最多 30 个、合计 200 MB，单个文件最多 50 MB。收集阶段可为每份原件选择对应资料项，保存文件时同时完成清单关联。一个资料项可选择一份主文件，其余附件可保留在文件列表中。

上传逐项显示“待上传、上传中、已保存、未完成”，失败原因显示在文件下面。成功项保留；点击“重试未完成项”只处理其余项。每项携带独立上传标识，网络中断后重试同一项不会重复生成文件版本。遇到多人修改冲突会暂停，先核对刷新后的工作单再继续。同名文件正常重新选择上传，仍会产生新版本。

未上传的文件队列只在当前页面保留；离开页面后需要重新选择。上传成功的资料以服务器为准，不依赖浏览器保存。文件类型和大小仍由服务端检查。

“缺件跟进”显示未收到或未豁免的资料。选择资料项，填写实际联系渠道、结果和下次跟进日期；记录保存到该客户月份。补件或豁免后，缺件自动消失，跟进历史仍保留。系统不自动给客户发送消息。必需资料未齐备或未完成独立豁免时，不能结束收集。

## WorkBuddy 交接

1. 进入经办处理，选择工作流、处理要求和输入文件。页面只列同名最新原件，勾选的文件版本会固定到执行记录。
2. 点击“建立任务并生成任务包”，当前工作单显示等待、打包、就绪或失败状态。可以直接下载、重试，无需跳转到后台任务页。打包任务归当前账号；同公司协作者可为同一执行记录生成自己的任务包。
3. 解压 ZIP，在 WorkBuddy 中按任务说明处理副本。包内含输入文件、摘要清单、提示词、输出要求、校验模板和 `return-manifest.json`。
4. 在工作单顶部选择“处理成果”并批量上传文件。展开对应任务的“回传此任务的成果”，读取任务包里的回传清单，或粘贴其内容。
5. 明确勾选本次成果，填写行数、金额核对和未解决事项后回传。服务端核对任务、输入摘要、公司和成果版本；拒绝多余摘要字段、历史成果版本、跨工作单文件和过期任务。相同回传重试不会重复推进流程。
6. 有 WorkBuddy 执行记录的工作单，送审快照仅包含当前批次明确回传的成果；未选中的内部草稿不会被自动带入送审及交付包。没有外部任务的手工处理工作单仍使用同名最新成果。
7. 结果仍须经办校验、独立复核，再由员工完成实际客户交付并登记证据。退回、更换输入或成果后重新按当前版本执行，已归档批次冻结。

页面状态“外部处理中”代表等待员工处理与回传，不代表系统已经调用了 WorkBuddy 或 AI。结构检查也不等于会计正确性审查。

## 团队管理

负责人进入“团队成员”，可以搜索姓名或账号、筛选在职和停用成员，并查看每人的授权客户数、经办和复核的未归档月份数。

选择成员和客户后，交接预览列出客户默认分工和该员工负责的在办月份。选择接手人员、填写原因，可明确勾选交接后撤销原员工的公司权限。保存共同完成授权、默认分工和未归档月份的转交；任一版本变化或角色不合适，全部拒绝并要求重新预览。已归档分工不修改，历史经办责任保留。

接手复核的人不能是该批次经办、历史参与者或提交人。负责人不能通过交接解除自己的全公司访问权，需另行调整角色。停用或降级会留下无人负责的客户或月份时，服务端要求先交接；保存账号变更后撤销旧会话。新建员工默认角色为经办，首次登录必须修改初始密码。

“运行与备份”用状态、时间和可用容量展示运行信息；失败任务范围明确为当前账号，可进入任务中心重试。不会用管理页面绕过后台任务的账号和公司隔离。

## 虚构客户验收

`test/collection-lifecycle.mjs` 在独立 Docker 测试项目中创建虚构团队和客户“青禾商贸”。除测试账号初始化外，业务步骤均通过真实 HTTP API，任务包由独立 Worker 生成并实际下载校验：

- 建档、默认分工和首月建立；缺件阻止提前流转。
- 跟进记录、过期版本拒绝、原件逐个上传并关联；非法文件拒绝、同一上传重试去重。
- 两轮任务包生成与下载，逐份核对 SHA-256；按协议模拟外部处理，未调用 WorkBuddy AI。
- 回传明确选择的成果；多余摘要字段和旧成果拒绝，重复回传只读返回成功。
- 自审拒绝、复核退回、更正后重新回传和复核，上传虚构交付证据并归档；保留两次复核记录。
- 内部草稿未进入送审快照；归档后上传被拒绝。
- 未交接员工停用被拒绝；交接快照冲突被拒绝；成功转交后旧授权立即失效，历史归档分工不变。
- 新增跟进表的跨机构行级隔离。

原始结果写入忽略的 `.test/results/collection-lifecycle.json`。测试流程已加入持续集成。浏览器端实测缺件跟进保存、任务创建、原页状态刷新和 ZIP 下载；本机扩展限制自动选择本地文件，因此批量选择文件的完整浏览器验收尚未通过，上传及重试由真实 HTTP 验收覆盖。

新增第 009 号增量迁移，保存跟进记录及上传、任务创建的幂等标识。升级前备份数据库和私有文件；不覆盖旧版插件本机数据。
# 桌面操作布局

团队页以桌面使用为主：内容区限制宽度，资料上传、清单与缺件跟进并列；成果与复核记录并列。团队成员采用较窄的人员列表和独立详情栏，表单不再横向铺满大屏。小屏幕才折叠为单列，原有财务模块保持原布局。

从客户历史记录打开月份时，顶部期间随工作单同步切换。保存跟进或刷新工作单不会因重复写入最近访问而重置当前操作区。
