## 本轮范围

资料库和月度工作单共用服务端文件分页、筛选、汇总及按编号解析；个人版继续使用本地资料，只将列表截断改为本地分页。原有上传、搜索、类型和目录筛选、排序、引用、置顶、下载入口继续保留。

成果明确区分 WorkBuddy 任务成果、人工处理成果、排除本次送审的历史文件及已归档历史成果。新文件在上传时确定归属；历史文件只依据明确引用自动迁移，无法确定的由负责人或本月经办说明理由后确认。文件上传时间、文件名及上传人均不能代替任务归属证据。

涉及增量迁移：`010_result_ownership.sql` 增加成果来源、输入修订和任务修订关系；`011_file_paging.sql` 增加分页和同名最新版本查询索引。升级前仍须备份数据库与私有附件，不以直接降级数据库作为回滚办法。

## 1205 份真实附件验证

专项测试先生成 1205 个具有真实字节、合法私有路径及 SHA-256 摘要的附件，再建立索引。测试随后还产生新版本、成果和真实 ZIP，故最终保留的测试文件数会大于 1205。这里的 1205 是初始完整分页样本数，不是容量脚本中的索引占位数据，也不意味着执行了 1205 次浏览器上传。

已验证：

- 默认每页 50 条，逐页遍历全部 1205 条，编号集合完整且无重复；时间、大小相同的记录仍有稳定排序。上限 100 条，超限请求拒绝。
- 类型、目录、搜索结果总数和完整范围汇总不依赖当前页；`%`、`_` 按文件名中的普通字符搜索。
- 第 301、1001、1205 份等跨页文件可以按编号解析和下载，实际下载字节摘要与保存时一致。
- 从完整资料范围推荐工作流输入，第 1205 份银行流水可以进入建议。选定跨页文件后，实际任务包 ZIP 包含对应固定版本且逐份摘要一致。
- 将末页文件置顶后，它出现在全局第一页；原相对路径形式的置顶标识继续识别，另一账号不会继承该置顶。
- 同事新增附件、调整置顶或改变任务状态后，旧分页版本返回冲突；无版本信息的非首页请求拒绝。按编号解析仍能查看已选历史版本，并明确其是否仍可用于当前操作。
- 同名任务成果按任务分别判断最新版本；人工成果有独立来源范围。未确认、排除送审、已失效任务的成果不会混入可选回传或人工送审列表。
- 系统生成的任务包不充当交付证据；只读账号不能下载原件，仅已复核成果获得对应下载能力。
- 未授权公司、另一机构、外部任务编号均被拒绝；撤销公司权限后，既有会话的列表和编号解析立即失去访问能力。

测试采用真实数据库和文件系统；Fastify 注入部分不包含浏览器、反向代理及网络延迟。WorkBuddy 外部处理仍按显式交接协议模拟，未验证 AI 输出质量。

## 后续补充：团队版浏览器实际交付流程

2026-10-27（America/New_York），使用 `zy-finance-test` 独立 Docker 环境和虚构客户、虚构经办及独立复核账号，在浏览器完成：

1. 建立客户与首月工作单，设置一项必需资料并分配经办、复核人员。
2. 经办通过文件选择器批量上传两份虚构 CSV，将银行流水关联至资料清单，进入核对及经办阶段。
3. 创建一项任务并下载生成的 ZIP，核对包内输入文件摘要与上传原件一致。
4. 模拟外部处理，浏览器在对应任务上传两份成果，读取包内 `return-manifest.json`，选择两份文件并填写校验说明完成回传，随后提交独立复核。
5. 复核人员分别下载两份送审文件并核对摘要，提交通过；生成并下载交付包，确认包含两份送审成果且摘要一致。
6. 经办上传虚构交付证据，登记虚构交付方式并归档；刷新页面后再次看到该月已归档。

浏览器实际操作未发现该流程的附件上传或回传缺陷；没有向真实客户发送资料。登录前会话检查出现预期 401，测试网站图标请求出现 404；刷新并重新进入页面后控制台未报告错误。此项只覆盖一家公司、一个月及一个任务；未在本次浏览器流程中验证并行任务、退回重开、失败重试或大批量选择。WorkBuddy AI 未实际执行，结果文件由验收人员模拟。

## 三个 Agent 的交叉复查

三个子 Agent 分别负责分页与真实附件、成果归属与交付、原版兼容与跨页选择，主 Agent 负责整合及浏览器验收。复查覆盖接口授权、数据库策略、来源域最新版本、固定引用和界面选择状态，不只检查排版。

本轮复查识别并处理了以下边界：

| 问题                                                               | 处理                                                                                   |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 先统计再取页时遇到并发上传，页数据与版本不一致                     | 同一只读可重复读事务读取汇总、置顶及页数据；变更后要求刷新分页版本                     |
| 文件不在当前页，引用或回传选择丢失                                 | 选择保存固定文件编号，使用独立解析接口核对，不从当前页重建选择                         |
| 历史版本可以解析，却被错误标为仍可操作                             | 同时返回可下载、可引用、是否最新及当前是否可选；旧源文件和旧成果不能作为当前最新候选   |
| 同名文件在不同任务之间相互覆盖“最新”判断                           | 原件按工作单、用途、文件名；成果进一步按来源和任务区分                                 |
| 旧未归属文件补归属后与新来源域撞版本，旧全局高版本还可能压过新成果 | 目标来源已有同名成果时拒绝合并，要求明确排除或确认正确的独立执行；不重编号、不猜测归属 |
| 变更任务或成果后沿用旧审批                                         | 修改使审批失效，保留旧记录并重新提交独立复核；修订生成新执行，取消保留审计             |

## 接口与兼容说明

- 新分页入口为 `/api/v1/companies/:id/files/page` 和 `/api/v1/orders/:id/files/page`。公司入口必须指定期间；支持用途、文件类型、目录、搜索、来源、任务、最新版本和置顶筛选。
- 响应区分 `rows`、`filteredTotal`、`scopeSummary`、`facets` 和 `pageVersion`。每页默认 50、最多 100；排序含唯一编号兜底。翻页携带当前版本，变化时返回 409，由界面提示并刷新第一页。
- `/files/resolve` 按明确编号解析，单次最多 100 个，返回可访问记录与不可用编号，不返回外部公司的文件详情。它能解析历史引用，不把当前页或“仅最新”筛选当成引用全集。
- `/companies/:id/files/suggestions` 从完整授权资料范围匹配最多 8 条建议，避免只在已加载的前 50 条寻找输入。
- 旧数组式文件接口继续保留其原有兼容行为；新增资料库及选择器使用分页入口。个人版不连接团队数据库，也不因本轮改动覆盖本机存储。
- 上传及成果回传的限制独立于列表分页：单次输入选择、任务回传选择、人工送审选择各最多 100 份；批量上传仍为每批最多 30 个、合计 200 MB、单文件 50 MB。
