# WorkBuddy 团队接入验收记录

## 本次实际验证

- 使用本机 WorkBuddy 桌面版和用户信任的临时 MCP 连接器，在隔离 Docker 数据库中处理一名虚构客户。客户建档、资料收集和人员分工通过团队服务完成。
- WorkBuddy 实际调用 MCP 读取工作单、创建执行、生成和下载任务包、核对输入摘要、上传成果并回传。测试只包含两条虚构流水，金额分别为 100.00 和 200.00 元。
- 第一份成果缺少要求的独立表格；第二份的异常明细用说明行表示零异常，可能被机器误计为一条。两次成果均在送审前保留并创建新修订；第三次主表两条、合计 300.00 元，异常表只有表头，另附校验说明。缺失余额和名称映射资料被注明为测试范围之外，未声称完成银行对账。
- 测试脚本以虚构复核员身份通过服务端下载三份成果，核对 SHA-256、行数和金额。经办自审被拒绝；脚本使用另一名虚构员工账号执行复核，通过后生成交付包，核对包内文件及摘要，记录虚构交付证据并归档。历史保留三次执行。这验证的是角色和流程控制，并非真人财务复核。
- 独立隔离数据库测试覆盖账号、公司权限、同一会话撤权、附件分页、任务成果归属、复核与当前设备退出。员工登录在虚构账号的 Windows 交互终端实际输入，密码未回显；本地会话经当前 Windows 用户的 DPAPI 加密。
- 工作台 CLI 以真实 Windows 进程连接虚构团队服务；Windows 下通过命名参数和 JSON 标准输入验证参数传递。用户提供的 WorkBuddy 会话测试结果显示，WorkBuddy 单独调用 CLI 的 `me` 和 `order` 命令成功读取虚构员工和已归档工作单，没有使用 MCP；这次桌面会话的 CLI 验收范围仅为只读查询，写操作由独立集成测试覆盖。

本次真实 WorkBuddy 测试适用范围是 MCP 与虚构资料的协作链路，不证明 AI 输出对真实账务、税务或财务判断正确，也不代替员工独立复核。正式使用前需按团队权限与数据政策另行验收。
