# 多 Agent 功能验收与问题清单

日期：2026-10-27。三个独立 Agent 分别检查搜索、月度交付、原版兼容；主 Agent 复核修复并开展浏览器验收。全部业务样本来自独立测试环境的虚构数据。

## 结论

本轮发现并修复了真实缺陷，不能把原来的版本视为已经验证可靠。主要路径现已通过真实数据库、HTTP、独立 Worker 和浏览器检查；这不代表所有路径都没有 bug。

| 用户关心的问题 | 结果 |
| --- | --- |
| 客户搜索是否正常 | 修复特殊字符误匹配、当前公司被搜索隐藏、迟到查询覆盖和分页边界。名称、编号、特殊字符、分页、未授权公司、跨机构及撤权后的旧会话检查通过。 |
| 月度交付是否有 bug | 找到旧成果沿用和导出版本漂移两项重要问题，已修复。虚构客户完成建档至归档；Worker 中断后恢复且仅生成一份成果。 |
| 原版与团队版能否兼容 | 原版模块继续复用，按公司与期间保存到服务器；修复保存队列、偏好、文件标识及刷新跳页。旧备份和大量文件仍有下述边界。 |

- Edge 桌面及390×844检查；窄屏页面宽度与滚动宽度均为390，目标页面控制台未发现错误。

## 仍需完善的边界

1. WorkBuddy 外部处理按任务包/回传协议模拟，未验证实际 AI 内容质量。当前成果归属工作单；时间与版本限制不能代替并行执行时严格的一对一成果关联，应继续完善。
2. 旧 JSON 作为历史导入，不能当作新审批证据；原始附件需另行上传。旧固定文件标识有歧义的，需重新固定。
3. 文件接口最多返回1000条，原版资料界面最多展示300条；大量历史附件仍需分页，不能宣称无限兼容。
4. 浏览器扩展限制自动选择本地文件；批量上传及回传已由真实 HTTP 验证，完整浏览器选择文件验收仍待补齐。
5. 检查不涵盖所有个人版模块的数据组合、长时间多人并发、真实财税判断或生产高可用。

下一轮优先完善文件分页和执行成果明确归属，再开展少量真实客户试运行。
